## Decisions (with rationale)

### Decision 1: In-file mode extension vs extraction
**Keep all modes in TitleReveal.tsx.** Rationale:
- Existing component already has 3 modes in one file with branching
- Adding 5 more follows the established pattern
- The shared infrastructure (props, refs, layout, C constants, useCurrentFrame) avoids duplication
- Extraction would need a registry pattern with no precedent in this codebase

### Decision 2: scramble mode—hybrid GSAP + frame-based
**GSAP handles stagger+tween, render handles character substitution.** Rationale:
- Random character generation is inherently frame-index-based, not a GSAP tween
- Using GSAP's `onUpdate` to swap innerText per frame is costly at 60fps
- Pure Remotion approach (used in TextScramble.tsx) is the correct pattern here
- Keep GSAP for the fade-in stagger; let each character's display content be computed from `frame` in the JSX return

### Decision 3: splitSlide—CSS clip-path per character with mirrored spans
**Duplicate each character as two `<span>` elements, `clip-path: inset` splits visible halves, GSAP drives opposite-direction `x`.** Rationale:
- Most reliable cross-browser approach for "split and slide" without canvas
- Each character is rendered twice (top half + bottom half), absolutely positioned at the same spot
- `clip-path: inset(0 0 50% 0)` on the first shows only the top half
- `clip-path: inset(50% 0 0 0)` on the second shows only the bottom half
- GSAP animates top-half `x: "-100%"` → `x: "0%"` and bottom-half `x: "100%"` → `x: "0%"` in parallel

### Decision 4: Catalog entries structure
Each new mode gets one composition entry in `catalogEntry.compositions` with sensible defaults. Naming convention: `TitleReveal{Mode}` (PascalCase matching existing: TitleRevealSlideUp, etc.).
New entries:
- `TitleRevealScramble` — text: "ZhanWeiFu"
- `TitleRevealDepthZoom` — text: "CINEMA"
- `TitleRevealShimmer` — text: "Elevate"
- `TitleRevealJellyWave` — text: "Bounce"
- `TitleRevealSplitSlide` — text: "SPLIT"
